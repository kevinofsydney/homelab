# Upstream documentation reviewed 2026-10-27

- [Proxmox VE administration guide](https://pve.proxmox.com/pve-docs/pve-admin-guide.pdf): cloud-init, VM management, roles, API tokens and backup storage. Verify installed version's docs before using token permissions or template commands.
- [Proxmox QEMU API source](https://git.proxmox.com/?p=qemu-server.git;a=blob;f=src/PVE/API2/Qemu.pm;hb=HEAD): resize uses PUT; POST configuration updates return an asynchronous task that must finish before the next operation.
- [Ubuntu cloud images](https://cloud-images.ubuntu.com/noble/current/): official Noble image and checksums.
- [Docker Engine on Ubuntu](https://docs.docker.com/engine/install/ubuntu/) and [Compose plugin](https://docs.docker.com/compose/install/linux/): official apt repository and Compose plugin.
- [Paperless setup](https://docs.paperless-ngx.com/setup/) and [configuration](https://docs.paperless-ngx.com/configuration/): PostgreSQL engine, broker, media/data paths and secret key. Current v3 configuration explicitly needs `PAPERLESS_DBENGINE=postgresql`.
- [Tailscale Linux install](https://tailscale.com/docs/install/linux) and [Tailscale SSH](https://tailscale.com/docs/features/tailscale-ssh): interactive join and access rules. Tailscale rules do not firewall other paths on the local LAN.
- [OpenCode CLI](https://dev.opencode.ai/v2/docs/) and [tool permissions](https://opencode.ai/docs/tools/): CLI package and shell tool boundary.
- [Official OpenAI documentation for Codex](https://developers.openai.com/learn/codex) and [Codex install example](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex): Codex CLI and interactive setup. Do not assume API entitlement from a ChatGPT subscription.
- [Ansible Proxmox collection](https://docs.ansible.com/projects/ansible/latest/collections/community/proxmox/index.html): available integration; the first milestone's Python provisioner avoids collection drift and third-party Python API dependencies.
- [Ansible support matrix](https://docs.ansible.com/projects/ansible/latest/reference_appendices/release_and_maintenance.html) and [pinned ansible-core 2.21.5 release](https://pypi.org/project/ansible-core/2.21.5/): control-node Python 3.12+.

The project does not pin unknown release digests. Reviewed public image references may be pinned in tracked examples; site-specific values remain in ignored configuration. Update versions through a change review. Hermes, Paperless-AI, Grok and the accounting system integration require fresh compatibility checks before implementation.

The [Codex CLI guide](https://learn.chatgpt.com/docs/codex/cli) and [OpenCode 2 guide](https://dev.opencode.ai/v2/docs/) establish their supported packages; exact installed releases are recorded in the public CLI manifest and bootstrap runbook. Application staging (2026-10-27): [Docker Engine Ubuntu packages](https://docs.docker.com/engine/install/ubuntu/), [Docker firewall behavior](https://docs.docker.com/engine/network/packet-filtering-firewalls/), [n8n Docker installation](https://docs.n8n.io/deploy/host-n8n/install-options/install-with-docker.md), [n8n security settings](https://docs.n8n.io/deploy/host-n8n/configure-n8n/basic-configuration/use-environment-variables/security.md), and the [n8n image registry entry](https://hub.docker.com/v2/repositories/n8nio/n8n/tags/2.44.7). The Docker package index, signing key checksum and n8n manifest digest were read over HTTPS on the preparation date. These observations do not establish live application health or recovery.

Paperless preparation (2026-10-27): the [v3.3.4 upstream Compose example](https://github.com/paperless-ngx/paperless-ngx/blob/v3.3.4/docker/compose/docker-compose.postgres.yml), [versioned configuration documentation](https://github.com/paperless-ngx/paperless-ngx/blob/v3.3.4/docs/configuration.md), and [settings source](https://github.com/paperless-ngx/paperless-ngx/blob/v3.3.4/src/paperless/settings/__init__.py) were reviewed for polling and PostgreSQL requirements. Image manifest digests were resolved from their public registries for linux/amd64. The chosen PostgreSQL 17 and Valkey 8 combination differs from the upstream example and has not been runtime-tested.

Immich research (2026-10-27): reviewed the [v3.3.5 release and Compose assets](https://github.com/immich-app/immich/releases/tag/v3.3.5) as a starting point. Its server, machine-learning, Valkey and extension-enabled PostgreSQL images form a release-specific set. The downloaded upstream example is research material, not a validated deployment; verify the then-current release and compatibility again before creating a stack.

Paperless startup service (2026-10-27): [systemd service documentation](https://www.freedesktop.org/software/systemd/man/250/systemd.service.html) describes oneshot services, timeouts and retry-on-failure; [systemd unit documentation](https://www.freedesktop.org/software/systemd/man/261/systemd.unit.html) describes the start-rate limit. The installed unit is a startup action, not ongoing health monitoring.

Uptime Kuma (2026-10-27): reviewed the [2.5.8 release](https://github.com/louislam/uptime-kuma/releases/tag/2.5.8), its [versioned Compose example](https://github.com/louislam/uptime-kuma/blob/2.5.8/compose.yaml), and Docker Hub manifest metadata for the pinned amd64 image. The [upstream setup text](https://github.com/louislam/uptime-kuma/blob/2.5.8/src/lang/en.json) recommends SQLite for small deployments. Docker socket access is intentionally omitted.
