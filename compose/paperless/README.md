# Paperless staging stack

This stack is private-only. The first installation is running on the separate application VM; see the [deployment handoff](../../agents/handoffs/paperless-deployment.md) for verified state, warnings and outstanding acceptance checks. QNAP backup setup is outside current scope at the operator's request; do not create a backup destination or job until asked. The application still requires its own verified QNAP media export. Docker packages are staged on the application VM; starting Docker's bridge networking requires explicit firewall-change approval. Do not put the development user in the `docker` group; Docker access is equivalent to root on that VM.

Copy `.env.example` to `.env`, recheck the reviewed immutable image digests against current releases, fill strong secrets, Tailscale bind IP and private URL, then `chmod 600 .env`. The example pins Paperless 3.3.4, PostgreSQL 17 on Debian Trixie and Valkey 8, reviewed on 2026-10-27. Paperless's matching upstream example uses newer PostgreSQL and Valkey majors; these chosen versions use the existing PostgreSQL 17 data-directory layout and Redis-compatible broker, but the combination still requires a live compatibility test. Do not change database major versions by changing the tag alone. Create `/srv/paperless/{postgres,valkey,data}` on the SSD and `media`, `consume`, `export` on the verified NFS share with correct image ownership. `scripts/deploy-paperless.sh` validates all paths and Compose without starting it. `--apply` starts it. Bind only to the VM's Tailscale IP and verify access controls from both trusted and untrusted devices.

For Paperless 3.3.4, network-folder polling uses `PAPERLESS_CONSUMER_POLLING_INTERVAL=30`; the older `PAPERLESS_CONSUMER_POLLING` variable is not used by this release. Verify an actual consume/OCR/search cycle on the mounted export after deployment.

`scripts/backup-paperless.sh` requires `PAPERLESS_BACKUP_MOUNT` in `.env` and writes a timestamped DB/media set on a separate verified NFS backup mount. It briefly stops the webserver. Test an isolated restore before production. Review release notes and update digests only through a change with a backup, health check and rollback plan.

Set `PAPERLESS_NAS_SOURCE` to the exact NFS `server:/export` value reported by `findmnt`. The deployment script rejects a different export even if its filesystem is NFS. `PAPERLESS_BACKUP_MOUNT` and `PAPERLESS_BACKUP_SOURCE` may remain unset or placeholders while backup is out of scope; the backup script independently validates its destination before use. Use unquoted `KEY=value` entries in `.env`; generate URL-safe secrets to avoid environment-file quoting differences. If backup is later brought into scope, review and validate it without `--apply` first; the backup script restores the webserver's prior running state.

After a VM reboot, confirm Tailscale is running, then run `sudo /opt/homelab/scripts/deploy-paperless.sh` and, if its checks pass, repeat with `--apply`. This triggers the configured NAS automount and checks its exact source before starting containers. The automount and gated restart were tested after a requested VM reboot; NAS-loss behavior remains untested. The application does not automatically start on boot.
