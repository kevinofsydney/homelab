# Uptime Kuma

A private, single-container uptime dashboard on the application VM. The 2.5.8 image is pinned by public registry digest. Its data is on the VM's local SSD, and the container has no Docker socket. The web UI binds only to the verified Tailscale IPv4 address; it is not a public status page. Its container has no separate CPU or RAM limit and shares the VM's resources. See [topology and resource diagram](../../docs/homelab-diagram.md).

The owner requested deployment on 2026-10-27. The service was staged with `ansible/playbooks/uptime-kuma.yml` using the private address from ignored site inventory, and launched with `homelab-uptime-kuma.service`. The container reported healthy, the private UI responded, the guest LAN-address probe was rejected, and a request from inside the container reached the Paperless login page. A read-only check on 2026-10-27 confirmed SQLite is selected, one account exists, and one active monitor named Paperless is present; its latest recorded heartbeat status was 1. The monitor checks the Paperless web endpoint, not document ingestion or NAS health. No notification destinations were configured at that check. Do not put passwords or tokens in Git.

The dashboard's data directory is a dedicated existing local ext4 directory on the VM SSD; it is not on QNAP. The startup wrapper checks Tailscale is running at the configured address and verifies the data path's filesystem before starting the container. Docker restart is disabled for this service so it cannot bind before Tailscale; its enabled systemd unit retries unsuccessful starts every 30 seconds. This configuration has not yet been tested through a reboot. A full Proxmox host reboot will not start the application VM while its Proxmox autostart setting remains disabled.

For status, run `sudo systemctl status homelab-uptime-kuma.service`, `sudo journalctl -b -u homelab-uptime-kuma.service`, and `sudo docker ps -a`. The systemd unit reports its startup action, not ongoing container health. A web monitor checks the endpoint response, not Paperless document processing or NAS data integrity. A monitor running on this same VM cannot independently report that VM's own outage. Configure notification delivery only when the owner chooses a destination. No public ingress, alerts, QNAP backup or Docker socket were configured.

For new deployments, review the version-specific [upstream Compose file](https://github.com/louislam/uptime-kuma/blob/2.5.8/compose.yaml), verify the current image digest and supply a private Tailscale IP in ignored inventory. Run the playbook with `--check --diff`, review and apply only with approval; run `/opt/homelab/scripts/deploy-uptime-kuma.sh` to verify without starting. Enable/start the systemd unit only after review. Existing configuration is not overwritten by the playbook; verify configuration on updates.
