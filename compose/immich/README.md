# Immich staging

Prepared from the official v3.3.5 release. Images are pinned to the release digests; the server and machine-learning containers use a site-selected non-root numeric UID/GID. The original upload data is on the dedicated QNAP export, while PostgreSQL, thumbnails, encoded video and model cache are on local SSD. See the [upstream custom locations guide](https://docs.immich.app/guides/custom-locations/).

This is a prepared configuration, not evidence of a working service; see the [deployment handoff](../../agents/handoffs/immich-deployment-2026-11-02.md). Copy `.env.example` to `.env` on the guest, mode 0600; fill the actual export, private Tailscale bind, numeric ownership and a random alphanumeric database password. After verifying the exact mounted export, create its `library` directory with the selected numeric identity and restrictive permissions. Pre-create the local directories and set the appropriate container ownership. Database storage must be on the local filesystem. The root-squashed QNAP share must grant the selected numeric identity access; do not broaden Plex or other shares.

`scripts/deploy-immich.sh` checks the exact mounted export, Tailscale address, existing local directories and Compose config. It only starts containers with `--apply`. Container restart is disabled so startup cannot bypass the mount gate. A reviewed boot unit and explicit NAS-loss tests are required before enabling automatic startup. Automatic database dumps stored on the NAS are not a complete backup: back up database and original files separately, including an off-NAS copy, and test a restore before relying on the library.
